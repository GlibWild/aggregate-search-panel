# 聚合搜索 · 多站点扫码登录面板

一款面向 Microsoft Edge（Chromium 内核）的浏览器扩展：把需要扫码登录的站点集中到一个侧边栏面板中，
统一管理登录二维码，并在登录后跨站聚合搜索、一键跳转到原页面。

- 站点列表管理：内置常用站点模板，也可完全自定义
- 扫码登录：登录页在弹窗中真实运行，扩展自动识别二维码并回传到面板
- 登录检测：扫描完成后通过关键 Cookie / 页面跳转自动确认成功
- 跨站搜索：一次输入关键词，按站点并发抓取并分组展示结果
- 一键跳转：点击结果直接打开目标站点对应页面
- 登录持久化：登录态由浏览器 Cookie 保存，扩展记录登录时间与过期时间
- 过期提醒：周期检测 + 系统通知 + 面板红色提示，支持重新扫码
- 可选凭证快照：AES-GCM 加密保存 Cookie，登录失效后可一键恢复
- 配置导入导出：站点配置可备份、迁移

## 快速开始

### 1. 构建

需要 Node.js 18+。

```bash
npm install
npm run build
```

构建产物在 `dist/` 目录。

### 2. 在 Edge 中加载

1. 打开 `edge://extensions/`
2. 打开左侧的“开发人员模式”
3. 点击“加载解压缩的扩展”，选择项目下的 `dist` 文件夹
4. 点击工具栏中的扩展图标打开侧边栏

如果当前 Edge 版本没有打开侧边栏，扩展会自动退回到独立标签页面板（功能完全一致）。

### 3. 添加站点并扫码登录

1. 切到“站点”页，点击“添加站点”
2. 选择内置模板（哔哩哔哩、掘金、微博、小红书等）或手动填写
3. 保存时浏览器会请求访问对应域名的权限，选择“允许”
4. 点击“扫码登录”，扩展会弹出一个登录窗口
5. 在弹窗中扫码（面板会同步显示二维码），登录成功后自动关闭窗口并标记为“已登录”

> 部分站点的二维码位于跨域 iframe 中，扩展无法读取，此时面板会提示“请在登录窗口中扫码”，在弹窗内完成即可。
> 登录成功后二维码卡片自动消失，登录状态由浏览器 Cookie 保持。

> 如果浏览器中已经登录了该站点，打开面板时会自动检测并显示“已登录”；
> 此时再点“扫码登录”，登录页会直接跳回首页，扩展会复用现有登录态并立即完成，不会停留在“未登录”。

### 4. 搜索

1. 切到“搜索”页，选择要搜索的站点（默认全部启用）
2. 输入关键词回车
3. 结果按站点分组展示，点击任意条目直接打开原页面

**结果域名过滤**：每个站点默认只保留属于该站点域名的链接，自动过滤广告、站外跳转与推广内容。
域名范围按主域计算（`www.bilibili.com`、`space.bilibili.com` 都算 `bilibili.com`），
可在站点编辑的“额外允许的域名”中补充短链域名（如 `b23.tv`），
或关闭“只保留本站域名的结果”。被过滤的条数会显示在对应结果组顶部，并附带被过滤的域名，
例如“已过滤 9 条站外链接（xhslink.com）”。

小红书、Pinterest 这类以图片卡片展示结果的站点，链接本身没有文字，
扩展会自动从卡片的标题元素或图片 alt 中提取标题，不会漏掉真正的结果。

抓取策略：

| 策略 | 说明 |
| --- | --- |
| 自动（默认） | 先后台请求搜索页；结果为空、需要登录或页面由脚本渲染时，自动回退隐藏标签页 |
| 仅后台请求 | 速度最快，无标签页闪烁；部分站点可能拿不到结果 |
| 仅隐藏标签页 | 在后台真实加载搜索页后再提取，兼容单页应用，可能短暂出现在标签栏 |

### 5. 登录过期

- 后台每 5 分钟（可配置）检查一次关键 Cookie，缺失或超过有效期即标记为“登录已过期”
- 同时监听 Cookie 变化，扫码成功后立即生效
- 过期时发送系统通知，面板顶部与站点卡片标红，点击“重新扫码”即可恢复
- 如果开启了“登录后自动备份登录凭证”，还可点击“恢复登录凭证”尝试直接恢复

### 6. 显示“未登录”但浏览器里已经登录？

1. 在站点卡片点击“检测”（或“更多操作 → 诊断登录状态”）
2. 检测未通过时会自动打开诊断弹窗，显示：
   - 是否已授权访问该站点
   - 实际读取到的 Cookie 名称（不读取值）
   - 当前配置的关键 Cookie 与匹配情况
   - 自动识别到的登录 Cookie
3. 如果诊断提示“检测到可用的登录 Cookie（例如 SESSDATA）”，点击“使用自动识别的 Cookie 修复”
4. 如果显示“尚未授权”，关闭弹窗后点击站点卡片上的“授权访问”
5. 如果读取数量为 0，请检查 Edge 扩展详情页中的“网站访问权限”，并确认浏览器未阻止该站点的 Cookie

扩展内置了一套高置信度的登录 Cookie 名称白名单（SESSDATA、z_c0、sessionid、web_session、SUB 等）。
即使关键 Cookie 未配置或名称不一致，只要浏览器中存在这些 Cookie，也会判定为已登录，并在状态说明中提示需要修正配置。

> 从旧版本升级后，扩展会为已有站点补充主域权限（`*://*.bilibili.com/*`）。
> 浏览器不会自动授予新权限，站点卡片会显示“尚未授权访问该站点”，点击“授权访问”即可。
> 这是读取 `domain=.bilibili.com` 登录 Cookie 的必要权限。

## 站点配置说明

大部分字段在“添加/编辑站点”中有提示，这里补充关键规则：

| 字段 | 说明 |
| --- | --- |
| 站点主页 | 用于识别站点、读取 Cookie、拼接相对结果链接 |
| 登录页地址 | 扫码窗口加载的地址，是二维码所在页面 |
| 搜索地址模板 | 必须包含 `{q}`，例如 `https://site.com/search?q={q}` |
| 关键 Cookie | 登录成功后才存在的 Cookie 名，多个用逗号分隔；是过期检测的核心依据 |
| 成功 Cookie | 可选，会自动合并进关键 Cookie 列表 |
| 登录成功 URL 正则 | 可选，浏览器地址匹配时视为登录成功 |
| 登录成功页面选择器 | 可选，登录后才会出现的元素 |
| 二维码元素选择器 | 留空时自动识别页面中的二维码图片/画布 |
| 结果条目选择器 | 留空时使用通用启发式提取（自动收集标题链接并过滤导航） |
| 只保留本站域名 | 默认开启，过滤广告与站外链接；域名范围包含主域及所有子域 |
| 额外允许的域名 | 站点常用短链/同公司域名，例如 `b23.tv`、`tmall.com` |
| JSON 接口模式 | 站点有公开搜索接口时优先使用，支持路径映射，例如 `data.list` |

抓取页面时可使用 `浏览器 DevTools` 查看目标站点的搜索页结构，再把选择器填入“高级设置”。

## 权限说明

扩展遵循最小权限原则：安装时**不申请**任何站点访问权限，添加站点时才请求该站点需要的域名。

| 权限 | 用途 |
| --- | --- |
| `storage` | 保存站点配置、登录元数据、设置与加密快照 |
| `sidePanel` | 侧边栏面板 |
| `tabs` | 打开登录窗口、后台抓取标签页、跳转结果 |
| `scripting` | 在登录页 / 搜索页中定位二维码、提取结果 |
| `cookies` | 判断登录状态、检测过期、可选快照备份与恢复 |
| `alarms` | 周期检测登录态 |
| `notifications` | 登录过期提醒 |
| `offscreen` | 使用 DOMParser 解析后台抓取的 HTML |
| 动态主机权限 | 仅限用户添加的站点域名（含主域通配，见下） |

> 登录 Cookie 通常写在站点主域（例如 `domain=.bilibili.com`）。浏览器要求扩展拥有**主域权限**
> 才能读到这类 Cookie，因此每个站点会同时申请 `*://www.example.com/*` 和 `*://*.example.com/*`。
> 从旧版本升级后，站点首次使用需要重新点一次“授权访问”。

## 安全与隐私

- 所有数据只保存在本地扩展存储中，不上传到任何服务器
- 扩展不注入常驻 content script，也不会修改目标站点内容
- 登录态由浏览器自身维护；扩展只保存登录时间、过期时间，不保存明文 Cookie
- “凭证快照”默认关闭，开启后使用 AES-GCM 加密；密钥同样保存在本地，属于本地混淆级保护，不能防御已经拿到扩展存储权限的攻击者
- 登录二维码截图仅存在于内存中，用于在面板显示，不会被写入磁盘

## 已知限制

- 站点页面结构与接口可能随时调整，内置模板中的地址/选择器失效时，请在“编辑站点”中更新
- 依赖 `SameSite` Cookie 或强反爬校验的站点，后台请求可能失败，请切换为“仅隐藏标签页”
- 二维码在跨域 iframe 中时无法直接读取，需要在登录弹窗中扫码
- 极端情况下登录成功检测可能延迟 1~2 秒（面板轮询间隔）
- Edge 的侧边栏在切换标签页时可能重新加载页面，搜索结果状态会重置，但站点与登录状态不会丢失

## 开发

```bash
npm run typecheck   # TypeScript 类型检查
npm test            # Vitest 单元测试（84 个用例）
npm run build       # 构建 dist
npm run verify      # 类型检查 + 测试 + 构建
npm run smoke       # headless Edge 冒烟测试（需本机安装 Edge）
```

`npm run smoke` 会用 headless Edge 加载构建产物，验证后台启动、面板渲染、站点保存/导出、搜索事件链路；
测试用的临时配置目录会自动清理。

目录结构：

```
src/
  background/          # Service Worker：消息路由、登录、搜索、会话检测、凭证快照
    search/            # 后台请求策略、隐藏标签页策略
  sidepanel/           # 侧边栏 React 面板
    components/        # 搜索页、站点页、设置页、二维码、编辑器等
  shared/              # 类型、消息协议、URL/会话/搜索工具、注入脚本、站点模板
    injected/          # 会被序列化注入页面的自包含函数
  offscreen/           # DOMParser 解析页
public/                # manifest.json、图标、HTML
tests/                 # 单元测试
docs/DESIGN.md         # 详细设计文档
```

更详细的设计（登录状态机、搜索回退、消息协议、数据模型）见 [docs/DESIGN.md](docs/DESIGN.md)。
